# 內部單刪除（回收筒）

時間：2026-11-27 19:38（Asia/Taipei）。未提交、未部署。

## 需求

問題管理裡「新建」的內部單要能刪除。使用者指定一定要進回收筒；其餘照規劃：

- 建立者本人也可以刪。
- 由客戶單轉來的單可以刪，客戶單回到需處置。

## 規則

- 可刪狀態：lookup `issue_deletable`（目前是 `new`）。
- 可刪的人：有 `issue.delete`（內部 PM），或建立者（且有 `issue.create`）。
- 已排入更新包的單不能刪。
- 刪除：設定 `issues.deleted_at`、`deleted_by`。所有資料列都保留，Issue model 的 SoftDeletes 讓它在各處消失。
- 還原、永久刪除：在專案管理的回收筒，需要 `project.trash`。永久刪除要輸入單號（不分大小寫）。
- 永久刪除會清掉以下資料：
  - 子表：addenda、comments、due requests、dependencies（兩個方向）、import rows、watchers、tags、ticket links。
  - 本單與其留言的附件；同一個檔案若還有別人在用就保留。
  - 會議事項保留，`issue_id` 改成 null，討論內容開頭加「（原關聯內部單 X 已永久刪除）」。
- 事件 `issue_deleted`、`issue_restored`、`issue_purged` 記在 issue。客戶看得到客戶單的事件，所以不在客戶單上寫事件。
- 客戶單：刪除後呼叫 `SettlementService::recompute`。客戶單沒有其它進行中的內部單時，`needs_pm_action` 設為 true，並通知 PM。
