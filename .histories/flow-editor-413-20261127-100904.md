# 流程圖線上編輯存檔 HTTP 413（2026-11-27 台北時間）

現象：在 drawio 編輯器匯入一個 313 KB 的 .drawio（948 個圖形）後按「儲存並退出」，回應 HTTP 413。

原因（正式站實測）：主機對 multipart 的一般文字欄位限制約 1 MB（1000 KB 通過、1100 KB 回 413，回應頁面是 Apache／LiteSpeed 的 413，經 openresty 轉送）；multipart 的檔案欄位測到 10 MB 都正常；PHP 的 upload_max_filesize 是 512M、post_max_size 是 800M。線上編輯器把整張「可編輯 SVG」放在文字欄位 `source_md` 送出，圖一大（或在既有圖上再匯入）就超過 1 MB。

修改：
- `cits/resources/js/flow/editor.js`：存檔時把 SVG 當檔案（Blob，欄位 `source_file`）送出，不再放在文字欄位。
- `cits/app/Http/Controllers/Flow/FlowController.php`：`saveRules` 接受 `source_file`（檔案）或 `source_md`（文字，MD 匯入和舊的呼叫方式），新增 `source()` 取內容；實際大小上限仍由 `flow.drawio_max_bytes`（5,000,000）在 service 檢查。

測試：`FlowTest` 新增一個測試（超過 1.1 MB 的 SVG 用檔案欄位新增，再用檔案欄位更新草稿，兩者都沒送時回 422）。全部 257 個通過。本機用同一份檔案匯出 xmlsvg 量到 332 KB（content 已壓縮）。
